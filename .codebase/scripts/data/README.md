# Puzzle corpus tools

- [Derived Stage 1 capture family candidates v1](prepare-lichess-derived-capture-families-v1.mjs) and [independent replay](audit-lichess-derived-capture-families-v1.mjs): training-only grouping of an already-audited static counterfactual report; current focal signature is too specific and its output does not authorize teaching. Run through [registered action](../../../python%20actions/lichess-derived-capture-families-v1-step.json).
- [Derived Stage 1 capture family candidates v2](prepare-lichess-derived-capture-families-v2.mjs) and [independent replay](audit-lichess-derived-capture-families-v2.mjs): coarser causal-role grouping of the same training-only flips; grouping frequency does not establish semantic family diversity or authorize teaching. Run through [registered action](../../../python%20actions/lichess-derived-capture-families-v2-step.json).
- [Bounded legal-branch contrast preparation](prepare-lichess-branch-contrasts.mjs): training-only teacher continuations with strict opposite capture outcomes; both first real-source attempts yielded zero families. Synthetic fixtures are software evidence only.
- [Capture comparison data contract](../../../documentation/design/puzzle-learning/lichess-capture-comparisons.md): the curator's explicit training-only matched-capture filter selects candidates; real histories/certificates and family/receiver gates remain required.

- [History-bound lesson preparation](prepare-lichess-lessons.mjs) restores standard-start source history and prepares independently checked all-legal capture-retention proof candidates. API samples are development-only; no graph load or neural delivery.
- [Single-API-fixture independent audit](audit-lichess-api-lessons.mjs) replays raw source PGN and checks exact legal coverage and consequences. [Measured scope and failures](../../../archive/early-development/research/reports/lichess-foundations-pilot-2026-10-21/README.md).
- [Candidate source audit](audit-lichess-source-candidates.mjs) independently replays training/validation setup and solution lines, proves their membership in the pinned CSV, checks source-game splits, piece/count limits and extraction/archive hashes. It never reads `final.jsonl` and explicitly denies history, relational-family, consequence or teaching qualification.

- [Lichess puzzle curator](curate-lichess-puzzles.mjs) streams verified CSV and retains a bounded, seeded sample. First decode the unchanged CC0 archive through the [Python standard-library extraction action](../../../python%20actions/extract_lichess_archive.py); pass its receipt with `--extraction-receipt`. The installed Node22 decoder stopped at leading metadata in a real `.csv.zst`, so direct compressed input now fails explicitly. The curator verifies source-line legality, source URL color/ply, source-game split grouping and selected duplicate positions, and writes both CSV and original-archive identities.

The curator creates **candidate source data only**. It does not retrieve full game PGNs, verify that the source line is forced or uniquely best, produce alternative-move consequence certificates, or authorize a neural update. Its output explicitly records those limits. Full-game history and exact board/history binding must be restored before any history-sensitive teaching event. A verified certificate must then be created with an existing project verifier or a new independently audited task verifier.

Full source games are retrieved with the registered Python action [fetch_lichess_game_pgns.py](../../../python%20actions/fetch_lichess_game_pgns.py). The development probe has verified one public game ID only. For training or validation, first complete the independent candidate-source audit, then pin the selected split and audit identities in a fresh action config. The final split is not accepted by the fetcher. The output manifest checks exact response-ID coverage; lesson preparation still binds each PGN to its puzzle position and history.

The complete source archive is scanned as a stream. Memory use is bounded by at most `limit-per-split` rows per split plus one input/decompression buffer; the default is128 rows per split. The curator's output directories must be new and empty by construction; each JSONL file and the final manifest are published with rename.

Example after obtaining the Lichess archive:

```powershell
node --max-old-space-size=256 .codebase/scripts/data/curate-lichess-puzzles.mjs --input .cache/lichess-puzzles-2026-10-21.csv --extraction-receipt research/reports/lichess-foundations-pilot-2026-10-21/extraction.json --out research/data/lichess-puzzle-candidates-v1 --limit-per-split 128 --min-rating 1200 --max-rating 2000 --themes fork
```

The filter above is only a sampling choice. `--max-pieces 6` restricts the post-setup solver position to the frozen Stage 1 piece budget; the default32 preserves earlier sampling behavior. A setup capture from seven to six pieces remains eligible. This limit does not resolve source history, supply a consequence, or establish relational-family separation. Puzzle ratings/themes are not consequence quality labels or calibrated neural feedback. Freeze a separate experiment protocol, source bytes, task verifier, resource bounds, matched feedback controls and recovery audits before any graph run.

- [Independent CSV batch lesson audit](audit-lichess-csv-lessons.mjs) reconstructs original source-game prefixes, verifies displayed FEN/history, checks registered piece-domain exclusions and replays every in-domain legal-action certificate. It requires a completed, pinned preparation package; no final rows, graph launch or family/learning acceptance. [Current registrations and evidence](../../../archive/early-development/research/reports/lichess-foundations-pilot-2026-10-21/README.md).

- [Expanded v2 legal-branch construction runner](prepare-lichess-branch-contrasts-v2.mjs): separate bounded follow-up to the v1 search that emitted one family at 512 branches. Registered Python action: [`lichess-matched-capture-legal-branches-v2-step.json`](../../../python%20actions/lichess-matched-capture-legal-branches-v2-step.json). No graph launch follows from search yield.

- [Expanded legal-branch producer v3](prepare-lichess-branch-contrasts-v3.mjs) uses a separately versioned 4096-branch helper. Its two emitted families are independently audited but do not establish family-disjoint splits or authorize graph training. Run/audit registrations: [`v3 search`](../../../python%20actions/lichess-matched-capture-legal-branches-v3-step.json), [`v3 audit`](../../../python%20actions/lichess-matched-capture-branch-audit-v3-step.json).

The validation-only Stage 1 continuation is registered in [the Python action](../../../python%20actions/lichess-validation-branch-families-v1-step.json): it searches only v7 validation rows and has a separate legal/source replay audit. One emitted family does not establish family disjointness or graph eligibility; final rows stay unopened.
For a larger Stage 1 held-out pool, use the versioned [validation-only sampler](curate-lichess-validation-puzzles-v1.mjs) and its separate [source auditor](audit-lichess-validation-puzzles-v1.mjs), registered at [the Python action](../../../python%20actions/lichess-validation-candidates-v1-step.json). The completed 1,022-row candidate sample passes source-membership and split audit only; it does not establish history binding, consequence proof, family separation or teaching eligibility. The sampler does not parse final puzzle fields and emits empty train/final files.
## Babysit validation history

The registered validation-only source loop is in [the v3 Lichess fetch action](../../../python%20actions/lichess-validation-source-history-v3-step.json), [v2 preparation action](../../../python%20actions/lichess-validation-lesson-preparation-v2-step.json), and [v2 independent audit action](../../../python%20actions/lichess-validation-lessons-audit-v2-step.json). The audited output contains 192 histories and 1,909 known capture-retention action outcomes. It does not qualify family separation or authorize graph learning. Versioned collectors preserve raw responses on parse failure; versioned history parsing accepts exact `/ID` and `/game/ID` Lichess routes.
