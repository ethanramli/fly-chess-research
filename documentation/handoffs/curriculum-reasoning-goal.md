Prepared 18 October 2026. Reading this file does not activate a goal. Execute it only when the researcher explicitly starts/resumes the curriculum reasoning goal. This is a research operating prompt, not an experiment registration, a trained model, or evidence of reasoning. Use the selected model, including Luna at low effort; a prompt does not change model settings or guarantee scientific judgment.

## 1. Fixed objective and completion test

The scientific aim is whether an organism-derived architecture can support reasoning. The operational target of THIS goal is the smallest reproducible example of learned, consequence-sensitive transfer to unfamiliar chess families and counterfactual positions. Preserve that distinction: the computational model includes engineered input, teaching and readout interfaces; it is not a living fly. A result on one principle is a narrow contribution, not domain-general reasoning or a low-energy replacement for arbitrary LLM tasks.

Finish only when all of the following have been verified from raw artifacts:

Do not rewrite this objective, its completion criteria or the frozen evidence standard to match an observed result. A genuine user-directed scope change must be explicit, dated and preserved alongside the earlier contract; compaction and model uncertainty are not authorization to change it.

1. G0 association, interference retention and reversal pass all original requirements in three effective computational replicas, with full replay and recovery evidence.
2. Starting at C01 and respecting every prerequisite, at least one chess stage passes ALL applicable D1-D8 and stage-specific gates in the authoritative frozen curriculum. This includes useful all-legal choices, consequence predictions, unfamiliar-family transfer, paired counterfactual sensitivity, informative-control advantage and uncertainty, retention, causal state removal/restoration and independent replay. Do not replace these gates with one impressive example or a lower new threshold.
3. Checkpoint selection used validation and per-criterion retention; final families stayed sealed until the registered final campaign. Learning is frozen for evaluation. Unaided and fixed-search results are reported separately. The unaided requirement cannot be rescued by engine/search success.
4. Shortcut baselines and nuisance/label-leak checks support the declared relationship-transfer interpretation. Show the delivered neural signal separately from the teacher's richer proof. Report computational replicas as computational replicas.
5. A preserved final evidence bundle contains exact commands, protocol/data/source/graph/annotation/model/memory/encoder/readout/policy identities, all condition/replica results, resource metrics, certificate and neural replay audits, recovery evidence, selection history and known limitations. List every applicable gate with measured value and artifact path. A separately implemented audit must recompute the result; a success flag from the training runner is insufficient.

Stop at the FIRST stage satisfying this complete standard. The twelve-stage curriculum remains the larger program; later lessons, 2000 Elo, a browser upgrade, environmental application, competition entry and journal submission are not extra completion requirements. Planning files and this prompt may never mark a scientific gate passed. Only then use the celebration required by AGENTS.md and mark the goal complete. If any required evidence is missing or disputed, remain incomplete.

## 3. Execute one bounded cycle, then repeat

This is a repeatable decision loop within one active goal, not recursive chat spawning or a new orchestration framework. At each cycle choose the first applicable action:

| Observed state | Required action |
|---|---|
| Owned relevant run/audit is live | Monitor using sparse logs/checkpoints and actual process evidence. Preserve its frozen source. Work only on independent inert preparation while it runs; keep graph work serial. |
| State is unknown | Resolve ownership/liveness/publication first. Do not launch a duplicate. |
| Run was interrupted | Verify pins and last COMPLETE published checkpoint; resume into a NEW directory using matching archived sources, same settings and exactly-once pending receipt recovery. Preserve previous invocation. |
| Completed result needs audit | Run the separately implemented applicable replay audit before treating it as a scientific result. |
| Stage gate passed | Save the full evidence and accepted snapshot under the versioning rules. If the goal's completion test passes, finalize; otherwise prepare the next prerequisite-linked stage. |
| Valid run failed a gate | Preserve the failure; classify it using development evidence and choose one discriminating next hypothesis. Do not silently extend that run or lower its threshold. |
| New learning regressed earlier behavior | Preserve the regression, inspect per-criterion trajectory and matched controls, then branch a new candidate from the latest compatible accepted parent. Never erase the failed trajectory or restore a snapshot inside its measured retention challenge to make it pass. |
| Missing software/proof domain blocks teaching | Implement only that necessary component, validate and independently check it, register/freeze it, then return to informative feedback experiments. |
| No defensible local step remains | Save a concrete blocker with evidence and the exact input required; follow the goal tool's blocking/lifecycle contract. No aimless reruns. |

For each NEW experiment, BEFORE any graph launch write one short registration in the established experiment/report structure:

- Failed gate and evidence; one hypothesis and alternative explanations.
- The smallest distinguishing intervention, predicted results and interpretation for pass, fail and unknown.
- Accepted/from-scratch parent as required by that experiment, allowed memory changes, fixed graph and all identity hashes.
- Teachable experiences with exact board/history/action/criterion, independently checked proof, pre-feedback unaided ranking and delivered signal; unknown produces no event.
- Informative and yoked absent/matched-shuffled/disabled conditions, equal exposure/timing/computation, actual distinct replicas and all required retention/counterfactual checks.
- Frozen training/validation/final split identities, selection procedure and gates, seeds, exposure/search/time/node/memory/storage limits, exact commands, stop/resume behavior and separate audit command.
- What result would authorize the next step. If it is a diagnostic, name the precise blocker and the feedback-enabled follow-up.

Then complete necessary code review/tests, freeze a copied source/protocol snapshot, run, audit, classify and update state. The independent audit is a separately implemented verification path with preserved identities, not a second statement from the same scoring code. If no adequate auditor exists, build/review it before making a claim.

Do not spend successive graph runs on activity-only probes while a feedback-enabled experiment is ready. Controls alone are not learning progress. Keep earlier-principle rehearsal and retarget the current error at the registered cadence; do not repeatedly teach a historical error that is no longer the model's preference.

## 4. Failure, regression and scaling discipline

Persist through negative results when a distinct, justified next action exists. A failed experiment is useful information, not universal impossibility. A possible diagnosis is a hypothesis until a controlled intervention distinguishes it.

Before tweaking, distinguish implementation/certificate errors, interrupted execution, representation collisions or missing relations, teaching delivery, update direction/timing, readout, interference, search candidate omission/refutation/horizon, and statistical/control variability. Inspect the real call path. Change one causal factor where feasible; new justified mechanism changes require primary-source support in the source-to-solution register, clear approximation limits and new matched tests.

Additional exposure/compute is a hypothesis. Scale only through a new bounded registered condition with matched controls and interpretable dose/quality measurements. Never turn a completed failure into an open-ended dose sweep, secretly choose a weaker shuffle, fit a label-producing readout or add unsupported negative plasticity. More hardware does not authorize parallel graph jobs, relaxed guards or higher spending by itself.

After three completed development experiments that add no useful information, do a short stagnation review before another graph run: list what each ruled out, what remains and which one next test would distinguish it. Continue independently if there is a justified test. Three learner failures alone do not mean the goal is blocked. Do not repeat the same source/data/seed/protocol run without a registered replication or recovery purpose.

Target changes using TRAINING evidence. Use validation only through the frozen selection procedure. Final-test observations never guide a fix, new encoder, curriculum ordering, parameter choice or dataset design. If final evaluation fails, that confirmatory campaign ends with a preserved negative result. Do not open new final sets until one passes. A materially new hypothesis needs an independently motivated new registration, a full attempt ledger, fresh untouched families and a declared plan accounting for repeated selection/testing; unresolved validity requires review rather than a claimed discovery. Re-auditing frozen outputs for integrity is allowed; retraining on them is not.

## 5. Hard boundaries

- From-scratch initialization, released neuron identities, sparse topology and fixed sign conventions stay intact. Persistent changes occur only in explicitly permitted, justified physiological state. Teachers supply experiences and consequences, not parameter deltas. No imported chess weights, supervised fitting or engine search as a substitute for endogenous learning.
- Keep full graph sparse and one position at a time. No dense adjacency or edge-by-batch tensors. Stream receipts/history and bound traces, checkpoints and storage. Use existing helpers rather than add dependencies, workers or infrastructure without necessity and measured justification.
- Graph experiments and audits run serially with node --max-old-space-size=256 and --cpu-duty 0.5, RSS at most 768 MiB and at least 256 MiB free physical memory. Record actual RSS, CPU/wall and the stopping bound. CPU duty is pacing, not a hard OS cap. Guard failures preserve checkpoints; do not immediately relaunch into an unchanged resource shortage.
- Do not mutate active pinned code, old source archives, accepted snapshots, final datasets or historical failure reports. New runs use new directories and compatible pinned parents. A partial checkpoint is never acknowledged. Volume checkpoint-01423.partial is not a valid recovery point; its historical last publication is 1422.
- Use minimal root-cause patches. For core math run npm test; for feedback/search/learning/persistence changes verify perspective, unknown handling, task/search separation, wiring, control invariance and exactly-once recovery. Reuse completed checks when pins have not changed; do not skip a newly applicable required check to save tokens. Documentation-only edits need no simulation tests.
- Record every mistake, invalid control, failed attempt and pivot when discovered, before moving on. Append dated evidence/limits/diagnosis/change/next-test entries. Link material changes from current status, decision log and journal navigation. Preserve old conclusions with dated corrections.
- No paid compute, purchase, external communication, public submission, publishing or deployment without explicit user authorization. Work locally within existing permissions. Do not read email or wait for a mentor before ordinary authorized research steps. Do not fabricate mentor advice or appoint a mentor by inference.
- No outside research from 1 October 2027 through 31 May 2028, as requested for final IB exams. Preserve a clean handoff before that interval; do not schedule training/monitoring that requires work during it. Resume only under the user's instructions. This prompt is not an OS scheduler.

## 6. Low-cost execution and durable state

Stay on the user's selected model/effort. Do not switch models or spawn subagents by default. Routine execution can be delegated to deterministic existing runners/verifiers, not to unreviewed AI-generated judgments. If low-effort analysis cannot establish a biological/causal claim, make the uncertainty explicit, finish useful local evidence collection and prepare one precise review question. Do not guess to preserve momentum.

Keep documentation/handoffs/curriculum-reasoning-state.md small (target at most 120 lines): timestamp, fixed-objective reminder, current stage/gate, verified accepted parent/manifest, active run/protocol/command/logs, last COMPLETE checkpoint and pending receipt, process observation time, claim-to-evidence paths, total attempt/resource ledger links, latest mistake, exact next action, fallback and real blockers. Separate observations from hypotheses and distinguish prepared/active/complete/audited/accepted. No secret credentials or unsupported progress percentages.

Update the state after each launch, checkpoint/resume transition, completed audit, pass/fail, pivot and before ending a turn or requesting compaction. Make handoff updates atomic with existing/native file facilities; preserve an existing valid copy if replacement fails. A failed handoff write does not erase an already-published experiment receipt: reconcile from raw artifacts before any repeat. Checkpoint transactions remain the runner's responsibility.

The compact state carries links; append-only experiment/journal records carry history. Do not build a duplicate database, repeatedly print full checkpoints, reread the entire repo, dump huge logs or search the web without a specific missing fact. Read precise sections with bounded output and resolve truncation before making claims. Record required metrics regardless of whether they look favorable.

While a long tool/run is active, use tool-supported waits/yields and informative milestone observations, not rapid empty polling. Keep user updates concise and satisfy the environment's communication cadence. Every continuation should perform useful work or a legitimate wait/recovery check; no token-burning filler calls. A status question gets a short answer, then work resumes unless the user stops it.

When the goal is active, don't finish ordinary turns with "shall I continue?" or an unexecuted plan. Persist through permitted next steps. Follow the actual tool lifecycle: completion needs proof; pause needs the user's request; budget limits stop work without implying success; blocked status needs the tool's repeated-blocker threshold and no meaningful independent action remaining. Never create a replacement goal or raise a budget to bypass a limit. No prompt guarantees weeks of unattended uptime or 1,000 perfect compactions: disk state, raw artifacts and user control provide the recovery path.
