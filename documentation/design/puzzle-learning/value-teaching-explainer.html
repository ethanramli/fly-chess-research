0. How to read any formula here

In plain words: A formula is just a recipe sentence with shorthand. "$s$" is not scary — it's just a nickname for "the chess situation right now." Whenever you see a new letter, ask three questions: what is it in real life?, when does it show up?, and can you give me one example? This page answers all three every time.
  • Letters = nicknames. $s$ = situation, $a$ = action (a move), $x$ = numbers describing the board.
  • Subscripts = labels. $x_i$ means "entry number $i$ in the list $x$." $h_j$ means "hidden unit number $j$."
  • Greek letters = knobs. $\lambda$ (lambda) = blending knob, $\eta$ (eta) = step-size knob, $\tau$ (tau) = volume knob, $\delta$ (delta) = "the difference / the mistake."
  • Arrows like $\leftarrow$ mean "update" — throw away the old value, store the new one.
Example sentence: "$\delta = Q_{SF} - Q_{fly}$" just means "mistake = teacher's score minus student's score." Positive = student was too gloomy. Negative = student was too optimistic.

1. Meet the characters (every variable, with a real example)

In plain words: Think of a chess lesson. There is a position, a student (the fly brain guessing), a teacher (Stockfish answering), and a report card (numbers recording who was right). Every letter below is one of those roles.
$s$the Situation

Real meaning: the full board + whose turn it is + castling rights + history.
When it appears: at the very start, before anyone moves.
Example: "White to move, king on e1, rook on h1, Black just played …Nf6."

$a$the Action

Real meaning: one legal move.
When: when we list choices.
Example: $a$ = "play Nf3". $A(s)$ = the whole list: {Nf3, e4, d4, …}.

$x$, $x_i$, $F(s)$the Number List

Real meaning: the board translated into 1s and 0s so a network can eat it. $x_i$ = slot $i$. $F(s)$ = "which slots are switched on."
Example: slot 712 = "white knight on f3" → 1 if present, else 0.

$d$how Long the list is

Real meaning: total number of slots (e.g. tens of thousands).
When: when we build the translator. Only ~30 slots are "on" at once — that's why it's fast.

$W, b, h$brain Wiring

Real meaning: $W$ = connection strengths, $b$ = starting nudges (biases), $h$ = middle-layer activity.
When: $W,b$ exist from birth and change with learning; $h$ is recomputed every position.

$v(s)$, $c$the Score

Real meaning: "how good is this position?" in pawn units. +100 = up about one pawn.
Example: $c = +150$ means White looks ~1.5 pawns better.

$q$, $\hat{q}$squished Score

Real meaning: the same score squished into 0–1 so huge numbers don't break training. 0 = losing, 0.5 = even, 1 = winning. $\hat{q}$ = "what the network currently predicts".

$r$, $z$reality + Target

Real meaning: $r$ = what actually happened (1 win / 0.5 draw / 0 loss). $z$ = the lesson target mixing squished score $q$ and reality $r$.
Example: engine said 0.7 but game was drawn (0.5) → target is somewhere between.

$\lambda$blending Knob

Real meaning: how much to trust the engine's opinion vs. the final result. $\lambda=1$ = only engine, $\lambda=0$ = only result.
When: chosen once before training.

$\eta$step Size

Real meaning: how big a correction to make after each mistake. Tiny = careful, huge = unstable.
Example: $\eta = 0.01$ means "move 1% of the way toward the fix."

$Q_{fly}, Q_{SF}, \delta$student, Teacher, Mistake

Real meaning: student's guess, teacher's answer, and the gap between them.
Example: fly says 0.4, Stockfish says 0.6 → $\delta = +0.2$ (fly was too gloomy).

$T$, $\tau$, $e_i$safe Signal

Real meaning: $T$ = teacher's voice with the volume capped at ±1 so it never shouts. $\tau$ = the volume knob. $e_i$ = "which connections were recently used and deserve the credit/blame" (eligibility trace).

2. Turning a board into numbers

In plain words: Networks can't see pictures — they read lists of numbers. So we give every possible detail ("white knight on f3", "black can still castle", …) its own light switch: 1 = present, 0 = absent. In any real position almost all switches are off. That's the whole speed trick.
Where does $x$ come from? Right after the position $s$ arrives, a fixed translator (the encoder) converts $s$ → $x$. Nothing has been learned yet — this is just translation.
$$x_i = \begin{cases} 1, & \text{if detail } i \text{ is present} \\ 0, & \text{otherwise} \end{cases}\qquad F(s) = \{ i \mid x_i = 1 \}$$
This says: "switch $i$ is ON if that detail is on the board." $F(s)$ is just the short list of switches that are ON.

📊 Picture: a sparse list (only 3 of 20 switches ON)

Each box is one slot $x_i$. Dark = 1 (detail present). Here $F(s) = \{3, 7, 15\}$ — only those three weights need adding (see next section). In real Stockfish there are ~10,000s of boxes but still only ~30 dark ones.
$$h^{(1)} = W^{(1)} x + b^{(1)}\qquad h_j^{(1)} = b_j^{(1)} + \sum_{i \in F(s)} W_{ji}^{(1)}$$
This says: "first impression = starting nudge ($b$) + add up the strengths ($W$) of only the switches that are ON." Skipping the thousands of OFF switches gives the same answer, much faster.
Chess example: White plays Nf3. Only a few details change ("knight left g1", "knight arrived f3"). So $F(s)$ changes by ~4 entries out of 10,000+. Everything else stays.

3. Why the computer doesn't start over every move

In plain words: If only 4 light switches flipped, why recount all 10,000? Just subtract the ones that turned off and add the ones that turned on. That running total is called the accumulator — the reason NNUE is "efficiently updatable."
Where do $R$ and $A$ come from? The moment a move $s \to s'$ is made. Compare old ON-list $F(s)$ with new ON-list $F(s')$: $R$ = removed, $A$ = added.
$$h_j'^{(1)} = h_j^{(1)} + \sum_{i \in A} W_{ji}^{(1)} - \sum_{i \in R} W_{ji}^{(1)}$$
This says: "new impression = old impression + weights of newcomers − weights of leavers." A handful of additions instead of thousands.

📊 Picture: incremental update

You never recompute from scratch — you adjust. That's the entire NNUE speed idea.

4. The mini-brain: numbers in, one score out

In plain words: Stack a few layers: mix numbers → keep only positives (ReLU = "ignore bad vibes, keep good ones") → mix again → one final number: "how good is this position?" Call all the knobs together $\theta$ (theta = the whole bag of $W$s and $b$s).
$$h^{(1)} = W^{(1)}x + b^{(1)}\qquad h^{(2)} = \mathrm{ReLU}(W^{(2)}h^{(1)} + b^{(2)})\qquad v(s) = W^{(3)}h^{(2)} + b^{(3)}$$
This says: line 1 mixes the board numbers; line 2 mixes again and zeroes out negatives; line 3 squeezes everything into a single score $v(s)$. Shorthand: $v(s) = f_\theta(s)$ = "the brain with settings $\theta$ scores position $s$."
Chess example: $x$ = "knight on f3, pawn on e4, …" → hidden layer notices "kingside development + center control" → output $v(s) = +60$ ("White slightly better").

5. Squishing big scores into 0-to-1 (WDL space)

In plain words: Being up 10 pawns vs. 5 pawns barely matters — both are "totally winning." But +0.2 vs. +1.0 matters a lot. So we squish pawn scores through an S-curve (sigmoid): near-zero scores spread out, huge scores pile up near 0 or 1. The knob $k$ (≈410) sets how fast it squishes.
Where do $c$, $k$, $q$ come from? After the network outputs $v(s)$, we rename it $c$ ("centipawn score") and push it through the squisher to get $q$. This happens in Stockfish's training kitchen, before any learning.
$$q = \sigma\left(\frac{c}{k}\right) = \frac{1}{1 + e^{-c/k}}$$
This says: "divide the score by $k$, then S-squish into 0–1." $c=+410, k=410$ → $q ≈ 0.73$. $c=0$ → $q=0.5$ (dead even).

📊 Try it: drag the pawn score, watch the squished value

Squished $q$ = 0.59 (0 = lost, 0.5 = even, 1 = won)
Notice: the curve is steep near 0 (small differences matter) and flat at the ends (mate vs. big material — both ≈ 1). That's deliberate: don't waste learning on "how winning is already-won."

6. Mixing "looks good" with "actually won"

In plain words: The engine's opinion ($q$) can be wrong. The final result ($r$) is truth but crude (one number for a whole game). So the target $z$ blends both. The knob $\lambda$ is the recipe: "70% engine opinion, 30% reality."
Where do $r$ and $z$ come from? After the game ends we know $r$ (1 / 0.5 / 0). Training pairs each position's engine opinion $q$ with the eventual $r$ to build the lesson target $z$.
$$z = \lambda q + (1-\lambda) r \qquad \hat{q} = \sigma\left(\frac{f_\theta(s)}{k}\right) \qquad e = \hat{q} - z$$
This says: "target = weighted average of opinion and reality. Prediction $\hat{q}$ = what the network says right now. Error $e$ = prediction minus target." If $e = +0.2$, the network is 0.2 too optimistic.

📊 Try it: the blending knob $\lambda$

Target $z$ = 0.64
$\lambda=1$ → target is pure engine opinion. $\lambda=0$ → target is pure result. Real training sits in between (often ~0.7).

7. Learning from mistakes (the only calculus idea you need)

In plain words: Mistake = prediction − target. Punishment = mistake² (squaring makes big mistakes hurt a lot more than small ones and ignores sign). Learning = nudge each knob a little against the mistake: "if being too optimistic, turn down whatever caused optimism." The nudge size = step-size $\eta$ × mistake × "how much this knob contributed" (the input $x$).
$$L_n = (\hat{q}_n - z_n)^2 \qquad w \leftarrow w + \eta\,\delta\,x,\;\;\; \delta = z - \hat{q}$$
This says: "punishment = squared gap. Fix = step-size × (target − prediction) × input." Target bigger than prediction ($\delta > 0$) → push weights up along $x$. That's it — this one line is the ancestor of every update on this page, including the fly's.

📊 Picture: punishment grows quadratically

Being off by 0.4 hurts 16× more than being off by 0.1 (0.16 vs. 0.01). So learning focuses on big blunders first — sensible.
The page's longer chain-rule steps ($\partial L / \partial \hat{q}$, sigmoid derivative $\hat{q}(1-\hat{q})$, dividing by $k$) just carry this same "mistake × contribution" idea through the squisher. Same moral, more bookkeeping.

8. Looking ahead: judging is not searching

In plain words: The network is a judge ("this position looks +0.5"). Search is the imagination ("if I go there, they go there, then…"). Search calls the judge at the leaves of an imaginary tree and assumes both sides pick the best line for themselves. Alpha-beta pruning just skips branches that can't matter: "they already have something better, so stop reading this line."
Where does search happen? At play time, after training. Training built the judge; search uses it. Don't confuse the two layers.

📊 Picture: a tiny minimax tree (White picks max, Black picks min)

Leaves are judge scores. Each foe picks the worst-for-you reply; you then pick the better branch (here Nf3 → +0.3 beats e4 → −0.2). Pruning (α/β) skips proving what can't change the pick.
$$V(s) = \max_{a \in A(s)} \min_{b} V(s'_{a,b})\qquad \text{prune if } v \ge \beta \text{ or } v \le \alpha$$
This says: "value of a position = your best move assuming the foe answers best. Stop exploring a branch once it's provably too good (≥ β) or too bad (≤ α) to be chosen."

9. The fly student and the Stockfish teacher

In plain words: Now swap students. The fly brain guesses a value $Q_{fly}$ for a move. Frozen Stockfish (fixed version, fixed depth, fixed settings — like a sealed answer key) gives $Q_{SF}$. The mistake $\delta$ = teacher − student. The fly then nudges its wiring a little along the features it just used ($\phi$). Crucially: Stockfish never reaches into the brain — it only supplies the answer key through a declared teaching wire.
Where do $Q_{fly}$, $Q_{SF}$, $\phi$ come from? $\phi(s,a)$ = the board-after-your-move, encoded like $x$ but from the mover's perspective. $Q_{fly} = f_\theta(\phi)$ = the fly's current guess. $Q_{SF}$ = Stockfish's frozen answer for the same $\phi$. $\delta$ is born the instant both answers exist.
$$Q_{fly}(s,a) = f_\theta(\phi(s,a)) \qquad Q_{SF}(s,a) = g_{SF}(\phi(s,a)) \qquad \delta(s,a) = Q_{SF} - Q_{fly}$$
This says: "student guess, teacher answer, gap." Same pattern as section 7 — only the teacher changed (pinned engine instead of game result).

📊 Try it: be the teacher — set both scores, see the lesson

Mistake $\delta$ = +0.20 fly was too gloomy → nudge up ↑
Positive $\delta$ = "cheer up" (strengthen what was active). Negative = "calm down" (weaken it). Size of nudge = $\eta \times \delta \times$ features used.
Pinned answer-key = fixed Stockfish version + binary hash + options + depth/time + side-to-move perspective + mate handling + score→target transform. Change any of these and the "teacher" is a different person — so freeze them before training and log them.

10. Keeping the teacher's voice at a safe volume

In plain words: Raw mistakes can be enormous ("off by 800 centipawns!"). Shouting that into a tiny biological wire would swamp everything. So we cap the signal at ±1 — a whisper-to-firm range. The knob $\tau$ sets what counts as "loud": small $\tau$ = even small mistakes sound loud.
$$T(s,a) = \mathrm{clip}\left(\frac{\delta}{\tau}, -1, 1\right) \qquad\text{or}\qquad T = \tanh\left(\frac{\delta}{\tau}\right)$$
This says: "divide the mistake by $\tau$, then clamp into [−1, +1]." Sign = direction (under- vs. over-estimate); size ≤ 1 = volume-capped. Tanh does the same smoothly instead of with a hard cut.

📊 Picture: clipping — loud mistakes get capped

Middle zone: signal grows with the mistake. Outer zones: capped at ±1 no matter how huge the blunder. Biology-safe by construction.
Project rule: the capped signal must travel through an identified pathway to an eligibility trace $e_i(t)$ ("who was active recently"), not be vaguely called "dopamine." Arbitrary scalars ≠ identified reward circuits. The trace $e_i$ in the simplest case just equals the features used: $\Delta w_i = \eta\,T\,\phi_i$.

11. The whole loop, start to finish (8 steps)

In plain words: This is the entire proposal as a bedtime story: sit at the board → imagine a move → student guesses → teacher answers → compute the gap → lower the volume → blame the right connections → save the nudge. Repeat thousands of times. Nothing here is search, and the teacher never edits the brain directly.
1. Sit at position $s$, pick a candidate move $a$
↓
2. Encode the after-move board $\phi(s,a)$
↓
3. Fly guesses $Q_{fly} = f_\theta(\phi)$
↓
4. Frozen Stockfish answers $Q_{SF}$
↓
5. Mistake $\delta = Q_{SF} - Q_{fly}$
↓
6. Safe signal $T = \mathrm{clip}(\delta/\tau)$
↓
7. Nudge $\Delta w_i = \eta\,T\,e_i$ (only recently-active wires)
↓
8. Save: $w_{new} = w_{old} + \Delta w$
$$\Delta w_i = \eta\,T(s,a)\,e_i(t) \qquad w_{new} = w_{old} + \Delta w$$
This says: "each wire's change = step-size × safe teacher signal × how eligible that wire is. Then commit the changes." Simple case: $e_i = \phi_i$ (the features you just used).

12. Why this is still "proposal," not "proof"

In plain words: The algebra above is correct the way arithmetic is correct — but a correct recipe isn't a finished cake. Before any learning claim, the project must freeze and test: what the fly predicts, which encoding, which Stockfish answer, which squish-and-cap, which wire it travels, which trace takes blame — plus boring-but-essential controls (no feedback? shuffled answers? plasticity off? result-only?). Until then $\delta = Q_{SF} - Q_{fly}$ is a plan, not a discovery.
  • what exactly the fly predicts
  • which board-action representation is used
  • which Stockfish score is the target (version/hash/options/depth locked)
  • which transform makes the teaching signal (bounded, signed, declared)
  • how the signal reaches the identified pathway + eligibility trace
  • controls: no-feedback, shuffled-target, disabled-plasticity, outcome-only

13. One-paragraph summary

Board → number list $x$ (mostly zeros) → fast running total (accumulator) → mini-brain → score $v(s)$ → squish to $q$ → blend with reality into target $z$ → learn by shrinking squared mistakes. Search is a separate layer that imagines moves and asks the judge for leaf scores. FlyChess teaching reuses the same "target minus prediction" lesson, but the teacher is frozen Stockfish, the signal is volume-capped at ±1, and credit goes only to recently-active wires. Freeze every interface and beat the controls before claiming the fly learned chess.
