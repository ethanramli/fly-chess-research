# Board and action cue encoder: engineered input interface

2026-10-05. Implemented experimental input interface; no learning gate is enabled.

The biological candidate previously received synthetic A/B stimulation. The requested puzzle program needs a fixed representation of its actual board and candidate action, without a translator trained to reproduce human moves or teacher answers. `chess-cue.mjs` now supplies that input boundary. It accepts a chess.js board with its history, a legal UCI move, and only the declared forced-mate task/horizon. Extra task fields such as puzzle ID, answer, motif or score are rejected. Encoding never applies the move, searches a future board or queries a verifier.

Features: piece colour/type/square, each piece token conjoined with the candidate, action origin/destination/promotion/moving piece, side to move, castling, legal en-passant context, halfmove clock and current-position repetition count. Piece/action conjunctions distinguish an action in different contexts; they do not assert a tactical relationship or supply a chess evaluation. The inventory is bounded at 128 tokens and history at 512 plies/65,536 PGN characters. Oversized histories are rejected rather than silently losing draw context. The candidate continues to require disjoint families and counterfactual tests; these features can support memorization as well as transfer.

The fixed SHA-256 projection selects from existing KC identities in the coarse candidate mapping. No puzzle ID or random cue per puzzle enters it. The mapping is rebuilt from pinned annotations and exact released BigInt root IDs before probing, and must reproduce the prior mapping hash. This is a direct experimental sensory substitute, not natural vision, olfaction or action coding. The compartment/receptor limitations of the 870-edge candidate remain unchanged, and whole-model adaptation remains outstanding.

Default encoder seed 9613, at most 64 stimulated cells, total current at most 24 and per-cell current at most 1.5. Multiple features can collide at one cell; a fixed label-free order drops excess cells. Every token-to-cell assignment, collision, dropped feature, retained cell and actual current is reported. Both collisions and dropping can erase action distinctions, so numerical diversity must be measured rather than assumed. Persistent neural state never changes during encoding.

## New label-blind calibration comparison

The earlier resting-reference clipping failed: synthetic cue responses below rest collapsed to zero. That failure is preserved. `gf-readout.mjs` defines a **new** input-domain calibration from naive responses to a fixed public panel, without outcomes or learned memories. Per GF, it freezes the observed min/max range. The engineered action score is the maximum of the two normalized values clipped to [0,1]; lower is preferred. Raw signed values and out-of-panel flags remain available so saturation cannot be hidden. Insufficient range disables the decoder. Calibration is a numerical interface hypothesis, not a fit to biological danger or evidence that its polarity is useful for chess.

The [frozen input panel](../../../archive/early-development/research/data/chess-cue-panel-v1/protocol.json) presents all legal actions at four predetermined positions: both colours of the engineering fixture, initial board and one-cycle repetition context. Initial-board controls are input probes, not claimed solvable mate tasks. The declared goal is visible task context; no answer/proof/search result is used. One candidate repeats per position. No feedback, plasticity or memory update occurs. Freeze this calibration before any later conditioning; never refresh it after observing learned choices or use final-test positions to choose it.

```powershell
node --max-old-space-size=256 .codebase/scripts/probe-chess-cues.mjs --out research/reports/chess-cue-panel-v1-2026-10-05 --cpu-duty 0.5
```

The driver stays sparse and serial, uses the 768 MiB RSS/256 MiB free-memory guard and heap 256, and atomically checkpoints each completed candidate. `--resume CANDIDATE_DIRECTORY/state.json` requires identical source/input/config/encoder/calibration-panel identities and a new output directory. Each full-graph probe verifies all graph and parameter hashes. Repeated probes must reproduce exactly. This panel covers 92 distinct board/action inputs and four repeated presentations; it establishes only engineered input sensitivity and calibration behavior, not successful choices, natural biological interfaces, puzzle learning or transfer.

The remaining link is a supported experience/credit schedule and an independently validated choice response under informative, absent, shuffled and disabled learning controls. Do not enable `learn` because the encoder/readout or this panel passes. Preserve original gamma4 and GF-clipping failures; test unfamiliar and changed puzzles under fixed search budgets before interpreting improvements as reasoning.
