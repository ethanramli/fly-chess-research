# Bounded frozen-memory assessment cache

Engineering proposal and implementation, 2026-10-07. Reuse exact assessment summaries during unchanged simulated state; no teacher ranking, reduced legal set or substituted neural evaluation enters the cache. Existing measured profiles locate repeated full-graph candidate presentations as the dominant expense. [Matched development benchmark](../../../research/data/assessment-cache-v2/README.md) compares the same before/repeated/teaching/after/repeated sequence.

[Cache module](../../../.codebase/src/puzzle-learning/assessment-cache.mjs) accepts a caller-supplied complete identity covering released graph/fixed model, dynamics, persistent memory, readout and encoder. The benchmark hashes fixed state on every request, including readouts/config/encoder identity and memory snapshot. Any identity change discards all cached panels. Keys include FEN, complete bounded PGN, task and ordered candidate list. Capacity is at most eight panels, 256 candidates per panel, with a 256 KiB serialized panel bound. The implementation stores no edge-by-batch tensors or neural activity. Scores are cloned so consumers cannot mutate future hits. Guards run on hits and misses.

The original encoder and learner remain frozen. Replay always runs a fresh forward pass through the existing verified-feedback receiver before observing activity; it does not obtain local KC/DAN rates from this cache. Teaching, restored memory or fixed-state changes invalidate cached values. Unchanged state can reuse an earlier assessment as an engineering shortcut because the existing dynamics reset every forward pass; this assumption would need revisiting if continuous activity or physiological time becomes persistent.

Cached repeats cannot satisfy a fresh-activity repeatability, retention or causal reset gate. Those scientific checks must call the original assessor or clear/bypass the cache. Frozen-source historical experiments remain unchanged. A workload speed result establishes only that repeated-summary work was avoided; larger acquisition/transfer runs need separate matched time-to-quality measurements before a training-speed claim.

No external algorithm or biological mechanism is imported here. This is a bounded engineering optimization of deterministic evaluations, with exact source/input identity and equality gates. [Existing profile](../../../research/reports/learning-iteration-profile-signed-weights-2026-10-07/README.md) and [earlier task-aware profile](../../../research/reports/task-aware-forcing-profile-2026-10-07/README.md) motivated the test.

The [cached-root PUCT benchmark](../../../research/reports/cached-root-search-v4-2026-10-07/README.md) tests the actual application: 32 identical root candidates run freshly for the repeatability check, then reused once when Monte Carlo evaluates the same root and memory. The child assessment remains fresh. Across this sequence, time falls 27.0% and presentations go from 112 to 80 while both searches still choose a verified failure. This is a local latency gain without a choice gain.
