## First engineering candidate

Prioritize a bounded episodic experience store: keep experienced input/activity descriptors, candidate actions, verified consequences, source certificates and versioned context. Use fixed retrieval over public input features; no backpropagation is required for storage or nearest-neighbour retrieval. Keep raw experiences separately rather than forcing every new association into the same synaptic scalar. Capacity/eviction and retrieval rules must be declared prospectively. Contradictory episodes can coexist, but selecting the currently relevant consequence remains a real problem; append-only storage alone does not solve it.

Candidate source: [Blundell et al., Model-Free Episodic Control](https://arxiv.org/abs/1606.04460), identified 2026-11-01 through its abstract and author-hosted paper listing. This is a literature lead, not yet a full-method replication or a source-backed prescription for this project. Review its actual update/representation rules before claiming adaptation. In particular, a best-ever-return cache must not be assumed suitable for changed contingencies.

The APL tree kernel remains a disconnected, tested arithmetic prototype and optional representation comparison. It is not a prerequisite for the engineered memory route. Do not spend further geometry work solely to unblock an external episodic store.

## What evidence would mean

Describe the tested system as FlyChess with engineered memory. Disclose the encoder, memory contents, retrieval/indexing, update/eviction rule, any retrieval-derived value or action ranking, and any search/teacher computation. Attribute performance to the complete system unless component controls justify a narrower claim.

Distinguish exact recall and similarity lookup from the researcher's reasoning criterion: applying multiple unrelated concepts to an unfamiliar problem. Before reasoning evaluation, freeze train/validation/final family boundaries, prohibit final-test teaching or memory writes, and predeclare counterfactual and compositional transfer tasks. A lookup-only controller with the same memory, retrieval and compute budget is a necessary comparator when retrieval can directly rank actions; also compare no-memory and mismatched-memory conditions. If lookup alone explains performance, report useful retrieval rather than claiming the connectome reasons.

A controlled engineering result may inform the reasoning investigation while leaving the original biological long-term-memory goal unmet. Do not quietly declare that original goal achieved or merge the two claims. No engineered memory or new experiment is implemented/launched by this scope note; the next implementation must be small, auditable and separately registered.
