# Research records

Find the evidence and history behind FlyChess. Start with [current research status](../documentation/current-status.md) for the latest conclusions or [research documentation](../documentation/README.md) for the questions and designs.

## Directory tree

<!-- directory-map -->
- [`reports/`](reports/README.md) — Experiment results, failed tests, software checks, and independent audits.
- [`journal/`](journal/README.md) — Dated discussions, experiment notes, mistakes, and changes in direction.
- [`literature/`](literature/README.md) — Papers and source notes, plus the [five-volume book plans](literature/writings/README.md).
- [`project/`](project/README.md) — Research aims, decisions, and permissions.
- [`outreach/`](outreach/README.md) — Contact research, planning, and draft correspondence.
<!-- /directory-map -->

[Early datasets and frozen protocols](../archive/early-development/research/data/README.md) and [earlier code snapshots](../archive/early-development/research/source-archives/README.md) live in the archive. The [path history](../documentation/relocation-map.md) helps resolve older references. Local run outputs live under `runs/` on the machine where the job ran.

## Adding research records

Keep reports, protocols, outputs, and checkpoints at their recorded paths. Add a link to a new record from its owning index in the same change. Use a dated journal entry to correct a past record. Put current conclusions in the status page and link them to their evidence.
