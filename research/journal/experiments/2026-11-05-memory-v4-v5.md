3. **Mistake (control design, found now, carried from v3-v5):** the gate has no "pick any capture" baseline. The ledger stores quiet moves as −1 (2,858 of 3,000 slots in seed 6101 are −1, 137 are +1), and Eyes v2 shows a capture differently from a quiet move. So "full beats none" and "full beats shuffled" can be met by learning *capture versus quiet move* alone, without judging which capture is safe. On the 573 v6 test positions (all have both a safe and an unsafe capture): random legal move = 23.4 (equal to the none arm), random capture = **250.1**. The interrupted seed-6101 full arm scored 130.9, below the random-capture rule. Limits: computed from the position labels, not run through the gate; the interrupted run is not evidence.
4. **Diagnosis (hypothesis):** the memory has learned mainly that captures resemble the stored +1 experiences; there is no evidence yet that it separates safe from unsafe captures.
5. **What changes:** v6's frozen gate is not altered. The v6 report will show the random-capture baseline and the score among captures only as descriptive, post-hoc comparisons. The next memory version's gate should include a capture-only comparator, written before it runs.
