# 2026-10-07 capture-retention task interface

The current relational cue accepted only forced-mate task names, so verified feedback could not yet express the simplest blocker-dependent consequence. I added a separate exhaustive one-reply certificate and receiver checker for whether a legal capture can be immediately recaptured. Unknown outcomes produce no teaching event. The verified-feedback router accepts this task, and relational cue v3 supplies only the public task name and board/action features; the certificate and outcome are not encoder inputs.

A two-candidate comparison reverses which rook capture survives when the blocker relation changes. Targeted tests also pass one verified success/failure through an eight-cell synthetic network and confirm the existing adapter updates memory. This checks plumbing only; it does not use the released graph or measure a learned choice/transfer effect.
