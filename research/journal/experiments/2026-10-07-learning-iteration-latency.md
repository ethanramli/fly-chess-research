# Learning iteration latency optimization

2026-10-07. The researcher emphasized that the current project is nowhere near the hundreds of millions of positions discussed for CESP and asked whether iteration speed should improve before volume grows. The existing run had useful fixed-fixture outcomes but consumed substantial time; this investigation measured a single learning cycle before attempting scaling.

The first profile was a read-only replay of one exact adaptive all-legal choice, independently verified consequence, local feedback and post-update ranking cycle, with two frozen naive baselines. It used 53 neural presentations and did not include Monte Carlo search. The baseline cycle was 60,253.05 ms wall and 30,296 ms CPU. Sparse recurrent propagation dominated the neural-forward time. A separate interleaved 12-sample kernel test found that precomputing each fixed graph sign times its current edge magnitude reduced median forward time from 188.28 ms to 130.89 ms; predictions and all recurrent activity buffers matched exactly.

The cache was implemented as derived state in `SparseTrainer`, with internal updates synchronized in neural memory, reversal memory, circuit restore/step and Adam. It preserves the graph, signs, plasticity rule and policy. Exact post-change replay passed: same move, certificate, persisted memory, complete all-legal ranking and fixed-parameter hashes. The cycle measured 45,661.48 ms wall and 23,640 ms CPU, a 24.2% wall and 22.0% CPU reduction on this one fixture. Peak RSS was 109.09 MiB; the additional cache uses 10.8 MB. Project tests passed 92/92.

This is a first engineering speed improvement, not a learning result. The fixture is a single familiar position, only one before/after cycle pair was timed, and Monte Carlo search was not included. It does not measure learning per verified experience, full-run time-to-quality or explain how to reach hundreds of millions of positions. Next measure a representative Monte Carlo/search iteration and a multi-fixture full cycle under matched time and resource guards before deciding how to scale. Keep the useful puzzle-learning and unfamiliar/counterfactual reasoning gates primary.

Follow-up: a correctly paced full-graph Monte Carlo profile on the development puzzle needed 22.68 s for two evaluated board positions, performing 48 separate all-legal candidate presentations (24 per position on average). Neural forward passes took 21.28 s including the runner's presentation pacing; cue encoding took 1.37 s. The evaluation cap stopped search after one completed PUCT simulation. No teaching feedback or plasticity was applied; the task board, lasting memory and fixed parameters remained unchanged. This confirms that search volume cannot be scaled cheaply with the current per-candidate full-graph loop. A first harness attempt double-paced work and is preserved as invalid timing; v2 uses the actual runner behavior.

Next investigate equivalent reductions in repeated recurrent computation while preserving all legal choices, per-position serial processing and sparse memory. A candidate shortlist may be measured only as a paired diagnostic against all-legal ranking and independently verified choice quality; reduced candidate counts alone do not show reasoning progress.

The existing forcing-candidate prototype was then improved to tag checks, captures/recaptures, moves touching the opponent's changed squares and newly created direct/discovered/double attacks. It sorts these heuristic categories and reserves quiet actions. A warmed software microcheck generated 16 candidates from 32 legal moves in a median 9.80 ms (50 calls). A repeated ABBA full-graph comparison of 32 legal candidates against a 16-candidate/four-quiet shortlist on the smothered-mate fixture reduced mean assessment time from 22.08 s to 12.47 s (43.5%). The all-legal and shortlist choices agreed at `c4b4` in both repetitions and independently verified as failure. Crucially, the shortlist included `c4g8`, the sole certificate-verified successful move, and the all-legal baseline included it too. Its score was 0.013221 versus 0.020617 for `c4b4`, giving a concrete 0.007396 decision-margin gap to investigate through verified learning. This is one favorable candidate-coverage result, while the wrong neural ranking persisted. Keep the generator out of live MCTS until multi-position, counterfactual and fixed-search-budget tests show whether this efficiency preserves useful choices. Earlier 14/24-candidate probes used the previous algorithm; at 14 candidates the old shortlist omitted the all-legal policy choice in one of two states. The first new report also had a wrong success-inclusion boolean and is preserved with a warning; v3 fixed and asserted it.
