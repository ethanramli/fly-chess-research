## 1. The researcher's goal (2026-11-17), as given

"Design a new memory system that the simulated fly can use to learn from experience and potentially support reasoning. Computational memory is allowed; biological realism is not mandatory. The memory may help the fly remember. It must not supply the intelligence we later attribute to the fly." Five requirements followed: define what enters and leaves; keep remembering separate from solving; support continued learning; make the claim defensible with memory-only and simpler-system controls; design before implementation, without assuming v8 is the answer. Later in the session the researcher asked for Problem Solving at deep-in-thought, with GPT-6.1 Sol reviewers on the school Codex account at xhigh effort.

## 2. Pivot: from a store that answers to a diary that only replays

**Before:** every engineered memory so far (long-term-memory v1, memory v2 to v8) answered at decision time. v8 returned the outcome-weighted average of the three nearest stored boards, which is a nearest-neighbour classifier: the store judged the moves. Evidence: raw input 383.2 and random features 362.6 beat the fly's key 349.3 with the same store (v8 `summary.json`, rechecked today: full 349.33, piece-value rule 294.67, all-legal 30.60 against 21.92). In the 2026-11-01 live pilot the store overrode the fly's own scores.

**After:** the replay diary stores only the lessons the fly received (board seen, move chosen, pulse delivered) and its only output is re-living a random old lesson through the fly's eyes and dopamine cells into the fly's own learning rule. It is removed before every test. Reason: a memory that is absent when the fly is judged cannot judge for it; what it can still do during practice is bounded by matched controls.

## 3. Mistakes found in my own check before review

1. **Biased control.** Revision 1's first draft used "recent-only replay" as the matched-practice control. During the B block it replays only B lessons, which adds B practice and speeds the loss of A, so the diary would beat it for the wrong reason. Replaced, before review, by filler replay (same number of steps, no chess content) and a yoked control (the same old-lesson replays, done before B starts).
2. **Overstated interference.** The draft said ideas A (legal recapture) and B (exchange value) "pull in opposite directions". Under the transfer protocol's rejection rules they are consistent under one combined rule; they conflict only for a learner whose connections mix the two features. Corrected: whether this fly is pushed back and forth is unknown and the no-diary arm measures it.
3. **Learner mismatch not stated.** Stage 1 copies the cubic-exit task, which used the learner that produced the forgetting failure, not the current revision-4 learner. Added as a stated limit: a stage 1 pass does not show the diary works with the current learner.
4. **Unverified reference.** The Robins 1995 DOI was written before it was confirmed; the first web search could not confirm it. Crossref then confirmed 10.1080/09540099550039318 (Connection Science 7:123-146). All 17 references were then checked against Crossref or the venue's record.

Fix: pass `-c windows.sandbox=unelevated`; a one-line file read then succeeded. The blocked outputs and logs are kept in [the review folder](../../reports/replay-diary-design-review-2026-11-17/blocked-attempt-no-local-reads/). ## 4. Review round 1 (revision 1, blob `62c72ba4`)

Three GPT-6.1 Sol sessions at xhigh on the researcher's main Codex account, each owning one assumption ([review folder](../../reports/replay-diary-design-review-2026-11-17/README.md)). All three: **approve with required changes**. 14 required changes, none declined, no reviewer contradicting another.

Mistakes in revision 1 that the reviewers found (recorded as mistakes, now fixed in revision 2):

1. **A real leak.** Revision 1 stored board text and superseded entries by exact board equality. The peer reviewer showed, with a graph-free check, that boards differing only in move counters give identical eye input, so invisible details decided which old lessons stayed replayable. Fix: store the delivered input, not the board.
2. **The teaching path did not match the contract.** The existing three-board path teaches certificate-selected moves and has no receipts; the learner delivers input and pulse in one pass, not one after the other. Fix: a four-step lesson boundary and one-pass replay.
3. **Stage 1 could not be copied "exactly".** The cubic task injects normalized Kenyon-cell codes, uses a prediction-scaled teaching level, and judges six-seed medians (retention passes at 0.7199 in aggregate while single seeds read 0.4203, 0.5941, 0.6832). Fix: an explicit adapter contract and per-seed rules.
4. **Controls that did not isolate their rivals.** The moved-timing arm dropped new-block replays; the shuffle changed reward and punishment balance per replay; arms learning from their own choices would see different lessons. Fix: keep every replay, shuffle per event, one fixed teacher-chosen tape for stage 2 (a disclosed clue).
5. **A retention rule that hid losses.** 32 acquired and 30 kept passed the net rule while only 14 of the original pairs needed to survive. Fix: a pair-by-pair kept-share rule and low-point snapshots.
6. **Overclaiming.** A failed mixed-order run was read as "no joint setting exists"; a pass was called "Property 2 with a disclosed aid"; beating one lookup was read as showing the fly, not stored cases, did the work. Fixes: feasibility witness only; renamed assisted retention; full-history case recall and a random-feature learner added; attribution limited to the listed controls.
